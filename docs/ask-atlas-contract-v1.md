# Ask Atlas structured and mixed evidence contract v1 (API #17)

Status: specification gate for API #18, #19 and #100. No Structured or Both capability is advertised as live by this document. The existing Literature service remains governed by `research-assistant-contract-v1.md` (API #14). Contract changes require a reviewed version bump and golden-case review.

## Product boundary and question classes

One responsive Assistant accepts an explicit `Literature`, `Structured`, or `Both` source mode; omitted mode means automatic routing within capabilities actually enabled for the caller. Automatic routing selects Literature for literature-only questions, Structured for identified Atlas measure/geography/period questions, and Both only for an explicit cross-source comparison. Ambiguous intent asks clarification. A user override is authoritative and is never silently widened. Return `requested_source_mode` (resolved mode), `actual_sources_used` (subset of `literature_evidence`, `structured_atlas`), and `outcome` even when no evidence is admitted. A missing capability is `SOURCE_UNAVAILABLE`, never a fabricated answer. No autonomous investigation, workflow initiation, consequential mutation, diagnosis, patient-specific advice, or hidden chain of thought.

| Class | Supported question | Permitted capability |
| --- | --- | --- |
| observation_lookup | What is a named measure for an identified county and governed period? | `get_observations` |
| geography_comparison | Compare the same measure/period across identified counties or a state and counties, only when governed grain and units are comparable. A state is not synthesized from counties. | `get_observations` |
| measure_discovery | Which governed measure/indicator expresses a requested concept? | `find_measures` |
| provenance_methodology | Where did a cited observation come from; what are its method and limits? | `get_evidence_metadata` |
| completeness_gap | Which requested county/period combinations lack a governed observation? | `get_observations` and explicit coverage of requested combinations; no absence-to-zero inference |
| mixed_context | How does structured evidence relate to relevant literature? | the above plus the existing Research Assistant literature capability; cross-source comparison only if scope is comparable |

Ambiguous geography, measure, period, comparison basis, or source intent yields `NEEDS_CLARIFICATION` with a bounded clarification request and no speculative tool call. Unsupported geography/time/filter/strata yields `UNSUPPORTED_REQUEST`. A request for arbitrary SQL/Cypher, direct warehouse or repository access, medical diagnosis, or mutation yields `SAFETY_REFUSAL`; do not execute it. General model background is optional, deployment controlled, visibly labeled, and permitted only after governed Lyme/tick evidence is insufficient. It is never admitted as Atlas evidence or a source-used badge. Default is off. No server-side conversation history is required.

## Exact typed tool inventory

These are in-process application-service capabilities, not model access to repositories, SQL, Snowflake schema, REST self-calls, or arbitrary Cypher. Snowflake Cortex Agent/Analyst and model-generated SQL are prohibited. Snowflake stays below the shared services. The typed call schema, typed result/answer schema, and golden cases are normative. Canonical `Measure`, `Observation`, `Source`, `Methodology`, `GeographyIdentity`, and `EvidenceReference` models from `public_contract.py` validate nested objects; the envelope schema does not replace or fork those models. No production tool route is created by #17.

| Tool | Input and bound | Output | Deadline |
| --- | --- | --- | --- |
| `find_measures` | Exactly one of governed `indicator_id` or bounded search text (1-120 characters), `page_size` 1-20; no arbitrary filter/sort | At most 20 canonical `Measure` records from one release | 3 s |
| `get_observations` | Canonical `ObservationQuery`: one `measure_id`, one `geography_type`, 1-20 unique FIPS IDs, `year` or complete date pair, no strata/filter, estimated annual logical result at most 200 | At most 200 canonical `Observation` records and one coverage row per requested geography/year combination; no truncation or continuation | 8 s |
| `get_evidence_metadata` | 1-20 unique observation IDs admitted by the immediately preceding observation result; no free-form reference or external ID | At most 20 records pairing canonical `Source` and optional `Methodology` with admitted observation ID (at most 40 resolved resources) | 3 s |
| `literature_answer` | Existing API #14 governed question and bounded history contract | Existing citation-grounded Research Assistant response; no second retrieval path | Existing 28 s request deadline |

`find_measures` searches only canonical measure `measure_id` and `label`, never definition or raw repository columns. Strip leading/trailing whitespace, collapse internal whitespace, and Unicode casefold both query and candidate fields. Match a contiguous normalized substring; order exact `measure_id` match first, then exact `label`, then other matches sorted by `measure_id`. `indicator_id` uses exact governed ID and excludes search text. More than 20 matches is `QUERY_TOO_BROAD` (no arbitrary first page or silent truncation); `page_size` smaller than match count also returns `QUERY_TOO_BROAD` so all admitted candidates are visible. Zero matches is `RESOURCE_NOT_FOUND`. Discovery never silently selects among multiple candidates: ask clarification unless the user supplied an exact measure ID.

Before any observation call, validate JSON schema with `FormatChecker`, then instantiate canonical `ObservationQuery` and call `validate_bounds(ceiling=200, annual=True)`. Validate each FIPS with `GeographyIdentity`; apply the selected measure's governed geography and temporal grain, unit, and supported strata. `start_date <= end_date`, unique IDs, and `geographies * inclusive annual buckets <= 200` are mandatory. An unsupported grain/geography is `UNSUPPORTED_FILTER`, no call; state rows are supported only when the governed measure/application service actually supplies them. Current county-only service must reject state requests. No synthetic state aggregate. The annual result must contain every requested year/geography slot, including explicit `absent` coverage for no row. A governed `MISSING` observation is `present` coverage with null numeric value. Other time grains need a reviewed contract version.

One request may resolve a measure then make one observation call and, if needed, one metadata call; `Both` may additionally call the existing literature capability once. No unbounded loops, automatic follow-on research, arbitrary joins, aggregates, client selected SQL, or user selected physical relations. Total structured tool wall deadline: 12 s; timeout is `SOURCE_UNAVAILABLE`. Tool result ceilings apply before execution; over-broad input is `QUERY_TOO_BROAD`, not partial results. No pagination or continuation in these v1 tool results. Errors are all-or-nothing: an error result has empty arrays, null release where unknown, and a stable `error_code`; no partial evidence from that result is admitted.

Metadata IDs are not model-selected source/method IDs. The service retrieves only observations already admitted in this request, reads their canonical `source_id`, nullable `methodology_id`, `release_id` and `evidence` fields, and resolves Source/Methodology by those IDs in the same release. For a provenance follow-up carrying a prior evidence reference, first re-read the observation using its measure/geography/period context through `get_observations`, then verify that the returned observation ID and reference match; if context is absent ask clarification, and if identity no longer matches return `RESOURCE_NOT_FOUND`. Browser history or a client-provided reference alone is never admitted evidence. Only `resource_type=observation` with matching `resource_id=observation_id` is admitted; stale/foreign/unmatched references are `RESOURCE_NOT_FOUND`. A null methodology ID yields null methodology, never an invented method. A nonnull unresolved source or method is `SOURCE_UNAVAILABLE`. If current release changes between discovery, observation, metadata, or final answer assembly, return `RELEASE_CHANGED`/`SOURCE_UNAVAILABLE`, discard all structured evidence, and ask for a new request; do not combine releases or silently retry. A mismatched metadata release is treated identically. Canonical public current-release services remain the backend path; #18 must not create historical reads to bypass this rule.

## Evidence and answer envelope

Structured evidence is a canonical `Observation` with its `GeographyIdentity`, measure ID and unit, period, value and `ValueState`, source ID, methodology ID/version, semantic version, release version, limitations, publisher/acquisition/processing timestamps when governed, and compact stable `EvidenceReference`. Metadata resolves from the same release. Do not manufacture null fields. `Source` and `Methodology` resources enrich provenance; the observation reference remains the stable citation target. Literature evidence keeps the existing PMID/PMCID/passage/quote citation model, configuration version, policy version, and literature `evidence_state`; do not coerce it into an observation.

`docs/ask-atlas-results-v1.schema.json` fixes tool and answer envelope fields and nullability. In a successful `get_observations` result, each canonical Observation has a matching `present` coverage row with its ID; each requested slot without a row has exactly one `absent` row and null ID. The union of coverage slots equals the requested geography/year product, with no duplicates. An absent slot is not a canonical `ValueState`. A successful metadata result has exactly one item per requested admitted observation ID, with a matching canonical Source and optional canonical Methodology. Error results have empty arrays and a nonnull error code. Result release must equal every nested resource release and the request's pinned release. `find_measures` returns only canonical Measure records; its `release_version` must match pinned release.

An answer envelope includes replay identifiers (`provider_id`, `model_id`, `prompt_version`, `tool_contract_version`, `routing_policy_version`, `configuration_version`, `assistant_policy_version`, `release_id`, and literature retrieval configuration version). Absent provider execution uses null model/provider IDs. `structured_evidence_refs` are canonical `EvidenceReference` objects, never bare display text, and every reference resolves to an admitted observation in the same release. `literature_citations` retain the API #14 citation objects and claim/passage identity. Each generated claim has at least one admitted structured reference or literature citation ID and may cite both; every cited ID must occur in the corresponding answer evidence collection. No claim may exceed the scope of its cited evidence. For non-`ANSWERED` outcomes, `claims` is empty. `actual_sources_used` includes a class only when at least one cited governed item from that class supports a returned claim; retrieved but unused material does not earn a badge. The replay release ID is null if no structured evidence was admitted.

`cross_source_state` is null unless Both admitted and cited both classes. It is `aligned` for compatible scoped claims, `partially_aligned` for overlapping claims with material limits, `discordant` for materially opposed comparable claims, and `insufficient_to_compare` when two admitted classes cannot be compared. Thus Both with two classes and incomparable evidence has `INSUFFICIENT_EVIDENCE` plus `insufficient_to_compare`; Both with one class unavailable has null cross-source state and an explicit limitation. Discordance shows both sides without forced resolution. An unsupported claim fails grounding and becomes `INSUFFICIENT_EVIDENCE` or `SOURCE_UNAVAILABLE`, never an uncited answer.

## Deterministic routing and outcome mapping

| Condition | Assistant outcome | Evidence/badge behavior |
| --- | --- | --- |
| unsafe clinical, arbitrary SQL/Cypher, mutation | `SAFETY_REFUSAL` | no calls, claims, or badges |
| missing required disambiguation | `NEEDS_CLARIFICATION` | no speculative calls or badges |
| malformed request, invalid FIPS/date, unsupported geography/grain/filter/strata, unknown exact measure | `UNSUPPORTED_REQUEST` | no admitted evidence or badges; retain underlying `INVALID_REQUEST`, `UNSUPPORTED_FILTER`, `UNSUPPORTED_STRATIFICATION`, or `RESOURCE_NOT_FOUND` code in tool result when a tool was called |
| estimated bound or search ceiling exceeded | `QUERY_TOO_BROAD` | no partial result/badge |
| timeout, current-release race, malformed governed resource, unavailable backend | `SOURCE_UNAVAILABLE` | discard affected class, no affected badge; preserve `RELEASE_CHANGED` when applicable |
| governed row absent or only nonnumeric/unavailable value states | `INSUFFICIENT_EVIDENCE` for a requested numeric answer | may cite a present missingness row as a limitation, but no numeric claim |
| API #14 `no_evidence` | `INSUFFICIENT_EVIDENCE` | no literature badge unless a cited passage was actually admitted |
| API #14 `capacity_limited`, `evidence_unavailable` or grounding failure | `SOURCE_UNAVAILABLE` | no literature badge |
| API #14 `safety_refusal` | `SAFETY_REFUSAL` | no badge |
| one source of Both unavailable and other has grounded evidence | `ANSWERED` only for a separable single-source subquestion; otherwise `INSUFFICIENT_EVIDENCE` | cite only admitted source; limitation names unavailable class; cross-source state null |
| two classes admitted but incomparable | `INSUFFICIENT_EVIDENCE` | both cited if comparison itself describes their distinct scope; `insufficient_to_compare` |
| grounded answer with supported requested scope | `ANSWERED` | badges only for cited classes |

The existing Literature-only HTTP contract/status and API #14 safety/grounding behavior remain unchanged. These mappings are for the future unified Assistant adapter and do not retrofit the literature endpoint. Automatic routing never widens an explicit mode. Unknown exact IDs are unsupported; ambiguous names ask clarification. General-model background, if enabled, is labeled separately and never resolves an unsupported or unavailable governed claim.

## Interpretation and privacy

Canonical public V1 `ValueState` is `OBSERVED`, `ZERO`, `MISSING`, `SUPPRESSED`, `UNAVAILABLE`, `NO_COUNTY_LINKED_RECORD`. `ZERO` is an explicitly governed zero, never inferred from absent rows. `MISSING`, `SUPPRESSED`, `UNAVAILABLE`, and `NO_COUNTY_LINKED_RECORD` remain distinct and do not support numeric comparison. Unexpected Data states fail explicitly instead of coercion. Applicability and completeness are separate dimensions and are reported only if governed, not inferred from value state. Observed and predicted/model outputs remain separate classes with method/version and uncertainty; a prediction never stands in for an observation or an observed trend. No prediction is offered until a separately approved governed ML resource is available. Period, publisher update, Atlas acquisition/processing, response time, and release time are distinct; old periods are not automatically stale. Each cited structured observation has one `freshness` item in the answer envelope, keyed by observation ID. `state=stale` or `current` requires a documented source-specific `policy_id`, governed `source_timestamp`, and `compared_at`; absent policy or timestamp gives `state=unknown` and nullable fields, not a fabricated current status. A stale answer shows the relevant timestamp and limitation and does not imply current conditions. Unavailable evidence and insufficient evidence produce bounded abstention, including when one source of Both fails.

Never log prompts, question/history text, retrieved passages, model output, citations with sensitive content, bearer/capability tokens, secrets, or raw IP addresses. Bounded categorical outcomes, duration, tool IDs, counts, and version identifiers are permitted for diagnostics. Do not expose chain of thought. Use existing request-level OTel/diagnostics; #20/#21 own formal experiments, cost controls, and monitoring infrastructure.

## Evaluation and promotion gate

`tests/fixtures/ask_atlas_contract_v1.json` pins routing/tool/outcome expectations for objective cases. #18–#100 expand these into executable service and grounded answer tests without changing expected semantics. A candidate model, prompt, routing policy, or tool-contract change must pass 100% of safety, source-scope, schema, citation identity, and missing-versus-zero golden assertions; at least 95% of all objective correctness/tool-selection/grounding assertions; and no regression against the current production baseline in abstention appropriateness. Evaluate on the same versioned fixture and record provider/model/config IDs, sample size, per-case results, and p50/p95 request latency and provider cost per answered request. Promotion also requires p95 no worse than the current production baseline and estimated cost per answered request no greater than the current baseline, or an explicit product-owner exception with the measured tradeoff. No baseline or paid run is claimed by #17; subsequent stories establish measurements before promotion. Human review is required for clinically sensitive or disputed synthesis. A zero critical-failure gate prevents a high aggregate score masking unsafe cases. This policy does not authorize spending or production deployment.

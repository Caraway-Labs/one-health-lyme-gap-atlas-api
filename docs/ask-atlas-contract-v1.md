# Ask Atlas structured and mixed evidence contract v1 (API #17)

Status: specification gate for API #18, #19 and #100. No Structured or Both capability is advertised as live by this document. The existing Literature service remains governed by `research-assistant-contract-v1.md` (API #14). Contract changes require a reviewed version bump and golden-case review.

## Product boundary and question classes

One responsive Assistant accepts an explicit `Literature`, `Structured`, or `Both` source mode; automatic routing is the default only within the caller's available source scope. A user override narrows the scope and is never silently widened. Return `requested_source_mode`, `actual_sources_used` (subset of `literature_evidence`, `structured_atlas`), and `outcome` even when no evidence is admitted. A missing capability is `SOURCE_UNAVAILABLE`, never a fabricated answer. No autonomous investigation, workflow initiation, consequential mutation, diagnosis, patient-specific advice, or hidden chain of thought.

| Class | Supported question | Permitted capability |
| --- | --- | --- |
| observation_lookup | What is a named measure for an identified county and governed period? | `get_observations` |
| geography_comparison | Compare the same measure/period across identified counties or a state and counties, only when governed grain and units are comparable. A state is not synthesized from counties. | `get_observations` |
| measure_discovery | Which governed measure/indicator expresses a requested concept? | `find_measures` |
| provenance_methodology | Where did a cited observation come from; what are its method and limits? | `get_evidence_metadata` |
| completeness_gap | Which requested county/period combinations lack a governed observation? | `get_observations` and explicit coverage of requested combinations; no absence-to-zero inference |
| mixed_context | How does structured evidence relate to relevant literature? | the above plus the existing Research Assistant literature capability; cross-source comparison only if scope is comparable |

Ambiguous geography, measure, period, comparison basis, or source intent yields `NEEDS_CLARIFICATION` with a bounded clarification request and no speculative tool call. Unsupported geography/time/filter/strata yields `UNSUPPORTED_REQUEST`. A request for arbitrary SQL/Cypher, direct warehouse or repository access, medical diagnosis, or mutation yields `SAFETY_REFUSAL`; do not execute it. General model background is optional, deployment controlled, visibly labeled, and permitted only after governed Lyme/tick evidence is insufficient. It is never admitted as Atlas evidence or a source-used badge. Default is off. No server-side conversation history is required.

## Exact typed tool inventory

These are in-process application-service capabilities, not model access to repositories, SQL, Snowflake schema, REST self-calls, or arbitrary Cypher. Snowflake stays below the shared services. The typed envelope and the golden cases in `tests/fixtures/ask_atlas_contract_v1.json` are normative. No production tool route is created by #17.

| Tool | Input and bound | Output | Deadline |
| --- | --- | --- | --- |
| `find_measures` | Exact governed `indicator_id` or bounded search text (1–120 characters), `page_size` 1–20; no arbitrary filter/sort | Up to 20 canonical `Measure` records with release/version metadata | 3 s |
| `get_observations` | Canonical `ObservationQuery`: one `measure_id`, 1–20 typed FIPS geographies, `year` or complete date pair, no unsupported strata/filter, estimated logical result at most 200 | Up to 200 canonical `Observation` records plus requested-combination coverage and release-bound continuation indicator; never truncate silently | 8 s |
| `get_evidence_metadata` | 1–20 canonical structured `EvidenceReference` IDs; no free-form query | Up to 20 matching `Source`/`Methodology` resources and unavailable-ID outcomes | 3 s |
| `literature_answer` | Existing API #14 governed question and bounded history contract | Existing citation-grounded Research Assistant response; no second retrieval path | Existing 28 s request deadline |

One request may resolve a measure then make one observation call and, if needed, one metadata call; `Both` may additionally call the existing literature capability once. No unbounded loops, automatic follow-on research, arbitrary joins, aggregates, client selected SQL, or user selected physical relations. Total structured tool wall deadline: 12 s; timeout is `SOURCE_UNAVAILABLE`. Tool result ceilings apply before execution where possible; over-broad input is `QUERY_TOO_BROAD`, not partial results. Canonical read errors map deterministically: malformed/conflicting input to `INVALID_REQUEST`; unknown ID to `RESOURCE_NOT_FOUND`; unsupported filter/strata to `UNSUPPORTED_FILTER`/`UNSUPPORTED_STRATIFICATION`; excessive estimated work to `QUERY_TOO_BROAD`; dependency failure/timeout to `SOURCE_UNAVAILABLE`. These retain RFC 9457 concepts; the Assistant outcome is separate from HTTP transport status.

## Evidence and answer envelope

Structured evidence is a canonical `Observation` with its `GeographyIdentity`, measure ID and unit, period, value and `ValueState`, source ID, methodology ID/version, semantic version, release version, limitations, publisher/acquisition/processing timestamps when governed, and compact stable `EvidenceReference`. Metadata resolves from the same release. Do not manufacture null fields. `Source` and `Methodology` resources enrich provenance; the observation reference remains the stable citation target. Literature evidence keeps the existing PMID/PMCID/passage/quote citation model, configuration version, policy version, and literature `evidence_state`; do not coerce it into an observation.

An answer envelope contains `contract_version`, `requested_source_mode`, `actual_sources_used`, `outcome`, `structured_evidence_refs`, `literature_citations`, `cross_source_state`, `limitations`, and replay identifiers (`provider_id`, `model_id`, `prompt_version`, `tool_contract_version`, `routing_policy_version`, `configuration_version`, `assistant_policy_version`, `release_version`, and retrieval configuration when literature ran). Absent provider execution uses null model/provider IDs. `structured_evidence_refs` are canonical `EvidenceReference` objects, never bare display text; each referenced observation remains retrievable with the canonical field set above. `literature_citations` retain the API #14 citation shape. Every material generated claim must cite admitted refs or passages. Retrieved evidence and generated synthesis must be distinguishable. `cross_source_state` is null unless Both has comparable evidence from both classes: `aligned` (compatible), `partially_aligned` (overlap with material scope/method limits), `discordant` (materially opposing), or `insufficient_to_compare` (scope, period, variable, or evidence prevents comparison). Discordance shows both sides without forced resolution. An unsupported claim fails grounding and becomes `INSUFFICIENT_EVIDENCE` or `SOURCE_UNAVAILABLE`, never an uncited answer.

## Interpretation and privacy

Canonical public V1 `ValueState` is `OBSERVED`, `ZERO`, `MISSING`, `SUPPRESSED`, `UNAVAILABLE`, `NO_COUNTY_LINKED_RECORD`. `ZERO` is an explicitly governed zero, never inferred from absent rows. `MISSING`, `SUPPRESSED`, `UNAVAILABLE`, and `NO_COUNTY_LINKED_RECORD` remain distinct and do not support numeric comparison. Unexpected Data states fail explicitly instead of coercion. Applicability and completeness are separate dimensions and are reported only if governed, not inferred from value state. Observed and predicted/model outputs remain separate classes with method/version and uncertainty; a prediction never stands in for an observation or an observed trend. No prediction is offered until a separately approved governed ML resource is available. Period, publisher update, Atlas acquisition/processing, response time, and release time are distinct; old periods are not automatically stale. Flag `stale` only against a documented source-specific freshness policy, show relevant timestamp and limitation, and do not imply current conditions. If freshness policy is absent, report `freshness_unknown`. Unavailable evidence and insufficient evidence produce bounded abstention, including when one source of Both fails.

Never log prompts, question/history text, retrieved passages, model output, citations with sensitive content, bearer/capability tokens, secrets, or raw IP addresses. Bounded categorical outcomes, duration, tool IDs, counts, and version identifiers are permitted for diagnostics. Do not expose chain of thought. Use existing request-level OTel/diagnostics; #20/#21 own formal experiments, cost controls, and monitoring infrastructure.

## Evaluation and promotion gate

`tests/fixtures/ask_atlas_contract_v1.json` pins routing/tool/outcome expectations for objective cases. #18–#100 expand these into executable service and grounded answer tests without changing expected semantics. A candidate model, prompt, routing policy, or tool-contract change must pass 100% of safety, source-scope, schema, citation identity, and missing-versus-zero golden assertions; at least 95% of all objective correctness/tool-selection/grounding assertions; and no regression against the current production baseline in abstention appropriateness. Evaluate on the same versioned fixture and record provider/model/config IDs, sample size, per-case results, and p50/p95 request latency and provider cost per answered request. Promotion also requires p95 no worse than the current production baseline and estimated cost per answered request no greater than the current baseline, or an explicit product-owner exception with the measured tradeoff. No baseline or paid run is claimed by #17; subsequent stories establish measurements before promotion. Human review is required for clinically sensitive or disputed synthesis. A zero critical-failure gate prevents a high aggregate score masking unsafe cases. This policy does not authorize spending or production deployment.
